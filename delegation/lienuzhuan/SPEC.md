# 發包 spec：列女傳 段落級標註

## 你要做什麼

讀 `delegation/lienuzhuan/bNN.md`，逐段判兩件事：

1. `domains`：這一段觸及哪些人生問題領域（下表 13 個 id，可以是空陣列）
2. `modes`：這一段用什麼方式說話（下表 8 個 id，可以是空陣列）

輸出寫成 `delegation/lienuzhuan/out/bNN.json`，格式見文末。

## 這部書是什麼

《列女傳》西漢劉向撰，收 104 則女性傳記。**每一則的結構固定成兩段**：

| 段 | 內容 | 典型長度 |
|---|---|---|
| 第 1 段 | 傳文：敘事，末尾多有「君子謂／君子曰……詩云『……』，此之謂也」 | 200–900 字 |
| 第 2 段 | 「頌曰：」四言韻語，把同一則濃縮復述一遍 | 30–60 字 |

少數章有第 3 段。**全書 208 段裡有 104 段是頌曰**，所以頌曰怎麼判，直接決定整部書的樣貌——下面單獨開一節講。

評斷有正有負：前面多數是稱許（母儀、賢明、貞順、節義、辯通），書末一組是譴責（妲己、褎姒、驪姬、夏姬、哀姜之類）。**兩種都照同一道閘門判，不要因為評斷是負面的就判空。**

## 唯一的通則性閘門

這是敘事體，中性物件替換測試在這裡失效（軼事裡的人就是內容本身，換掉就沒有這一則了）。改問：

> **把這一則刪掉，讀者少知道了什麼？**
>
> 少的是史料事實（誰是誰的女兒、嫁給誰、哪一年做了什麼、哪一國因此亡了）→ `[]`。
> 少的是對人的看法（人可以怎麼活、該怎麼被評價、人與人之間如何）→ 給領域。

## 頌曰怎麼判

**把頌曰當獨立的一段，用同一道閘門判它自己的文字。**三條具體規定：

1. **不要因為「傳文已經標過了」就把頌曰判空。**它是不是重複，不是判準；判準是它自己說了什麼。
2. **不要因為「這是四言讚辭」就反射填 VII。**很多頌只是把事件列一遍。
3. 差別在**頌裡有沒有對人的評斷**：
   - 「頌曰：珠崖夫人，甚有母恩，假繼相讓，維女亦賢……二義如此，為世所傳」——「甚有母恩」「維女亦賢」是評斷，過閘門
   - 「頌曰：夏姬好美，滅國破陳，走二大夫，殺子之身，殆誤楚莊，敗亂巫臣，子反悔懼，申公族分」——通篇在列後果，一句評斷都沒有。**這種要照實判**，過不過閘門你自己讀了決定，`reason` 寫出依據

**注意頌曰不是敘事套語。**「神色不變」那種是固定詞組、每處意思都一樣所以不承重；頌曰逐則不同、內容各異，不適用套語規則。

## 硬撈風險（本書最容易錯的方向）

1. **「君子謂／君子曰＋詩云」幾乎每一則都有。**它出現本身不是命中訊號——要看那句評斷在說什麼。「君子謂塗山彊於教誨」講的是教養，「君子善傅母之防未然也」講的是防患的做法，兩者不同格。
2. **引《詩》是論證手段，不是 XII。**「詩云：赫赫姜嫄，其德不回，上帝是依」是拿經典替評斷背書，不是在寫人與神聖的關係。
3. **感生神話不是 XII。**「行見巨人跡，好而履之，歸而有娠」「有玄鳥銜卵，過而墜之……誤而吞之，遂生契」是這一體裁的出身敘事，不是信仰實踐。**XII 要卡到最緊**：只有文本真的在寫人與神聖之間怎麼樣才給。
4. **出現性、婚姻、淫亂不等於 III。**III 問的是兩個人之間的什麼（愛、承諾、信任、被理解）。妲己、夏姬那幾則的重心是權力怎麼被敗壞、人怎麼作惡，那是 V 與 VII，不是 III。要給 III，得說得出這一則在寫兩人關係裡的哪件事。
5. **章名幾乎全是「某某妻」「某某母」「某國某女」。**章名有「母」「妻」不等於 IV。要給 IV，得是這一則真的在寫親子、教養、宗族、繼承或家內事，不是只因為主角的身分是母親或妻子。
6. **亡國、被殺、殉死是情節，不是 X。**X 是死亡、衰老、失去本身成為這一段在談的事。「遂敗牧野，反商為周」是結局交代。

## 判空風險（反方向，一樣要防）

不要因為「這是一部史傳」「這只是講某個古人做了什麼」就整批判空。這部書的體例本來就是**用一個人的事蹟去主張人該怎麼活**，該命中的地方要照實記。

兩個方向的錯法只有一個解：**逐段真的讀懂它在做什麼，然後照實記。**讀懂之後發現它就是譜系與事件交代，那 `[]` 就是正確答案；讀懂之後發現它在替一種活法背書，那就給領域。

## 13 個領域（`domains` 只能填這些 id）

| id | 名稱 | 涵蓋 |
|---|---|---|
| I | 存在與意義 | 人為何而活、意義從何而來、有無本末 |
| II | 自我與認同 | 我是誰、自我評價、身分、名與實 |
| III | 愛與親密 | 愛與性、被拒絕、承諾、信任與脆弱、溝通與被理解 |
| IV | 家庭與傳承 | 親子、宗族、繼承、教養、婚姻家內事 |
| V | 群體·社會·公義 | 孤獨與歸屬、友誼、我群他群與偏見、公義與權力、責任與領導 |
| VI | 情緒與內在生活 | 喜怒憂懼、內在經驗 |
| VII | 善惡·良心·品格 | 德性、良心、品格養成 |
| VIII | 工作·成就·召喚 | 勞動、職業、才能發揮、成就 |
| IX | 苦難·疾病·身體 | 痛苦、疾病、身體限制 |
| X | 無常·老·死·失去 | 死亡、衰老、失去 |
| XI | 自由·命運·改變 | 命定與自由、人能否改變 |
| XII | 信仰·神聖·超越 | 神聖、超越、信仰實踐 |
| XIII | 安頓·修復·平安 | 受苦之後如何自處、如何與處境相處 |

`Z-wisdom`、`X-modern`、`Y-nature` **不是領域**，絕不可出現在 `domains`。

## 8 個 discourse_mode（`modes` 只能填這些 id）

| id | 定義 | 判準 |
|---|---|---|
| `observation` | 陳述某物／某人實際如何 | 可被事實否證的描述句 |
| `proposition` | 主張某個因果或原理 | 有「A 故 B」的結構 |
| `prescription` | 規定應該如何 | 祈使或當為句 |
| `formalization` | 把規範化成可計算程序 | 有可執行的算法、方陣或制度表 |
| `narrative` | 用故事承載 | 有人物與情節 |
| `ritual` | 用儀節承載 | 規定動作、時序、器物 |
| `expression` | 第一人稱抒發而非第三人稱描述 | 說話者即當事人 |
| `worked_instance` | 以具體數字陳述一個問題實例及其答案 | 算書題例專用，**本書不會用到** |

要點：

- 傳文有人物有情節 → `narrative`，這是本書主導 mode
- 句末的「君子謂 X 賢」這類人物評斷是**品題**，走 `observation`
- 傳中人物的諫言若有因果推理（「不脩先王之典法，而用婦言，禍至無日」「河潤九里，漸洳三百步」）→ 加 `proposition`
- **對話被包在敘事框架裡時，主導 mode 仍是 `narrative`，不要因為有人說話就給 `expression`。**`expression` 要整段就是說話者自道、沒有敘事框架
- **頌曰是四言韻語但不是第一人稱，不給 `expression`。**它復述事件與評斷 → `observation`；若整首只在鋪陳情節，`narrative` 也可以
- **`modes` 不要疊到三個以上**，挑主導的一到兩個

## 硬規則

1. **`[]` 是合法答案**，`domains` 與 `modes` 都是。負面結果本身是資料。
2. **一段可多標領域，但不要濫用。預設一到兩個。**要標第三個，`reason` 裡必須寫得出「拿掉它這一段就少講了什麼」——寫不出來就是湊的，刪掉。
3. **不要更動 `chapter` 與 `para_index`**。章名就是傳名（「有虞二妃」「棄母姜嫄」「殷紂妲己」），**逐字照抄**；`para_index` 在每一章內從 1 重新編號，**回報時章名與 para_index 兩者都要給**。
4. **不要用你對劉向、對這些歷史人物的既有知識去補文本沒說的東西**，也不要判斷書中的道德立場對不對。你的工作是記錄這一段在做什麼，不是評價它。
5. 原文有錯字、脫文、引號不對稱（「君子曰：「二妃德純而行篤。詩云：「……」」），那是來源格式，不影響判讀。

## 輸出格式

寫到 `delegation/lienuzhuan/out/bNN.json`，UTF-8、LF、不要 BOM：

```json
{
  "batch": "b01.md",
  "rows": [
    {"chapter": "啟母塗山", "para_index": 1, "domains": ["IV"], "modes": ["narrative", "observation"],
     "reason": "禹三過家門不入而塗山獨任教訓，君子謂其彊於教誨，整則在寫教養怎麼撐起一個人"},
    {"chapter": "殷紂妲己", "para_index": 2, "domains": [], "modes": ["narrative"],
     "reason": "頌通篇列亡國經過與後果，沒有一句對人的評斷，刪掉少的是事件不是看法"}
  ]
}
```

**`rows` 必須涵蓋該批所有 (chapter, para_index)，一個都不能少、不能多。** 這是回填時的雙向檢查條件，缺漏會整批退回。

`reason` 一句話即可，**判 `[]` 的段落也要寫 `reason`**，至少要指出它在做的是譜系交代、事件敘述、還是評斷。

## 不要做的事

- 不要改 `translations/` 底下任何檔案
- 不要跑 git 指令（commit、reset、pull、checkout、stash 一律禁止）
- 不要改 `delegation/lienuzhuan/` 的輸入 `.md` 與 `MANIFEST.json`
- 只寫 `delegation/lienuzhuan/out/` 底下你這一批的那個 `.json`
