# 發包 spec：方言 段落級標註

## 你要做什麼

讀 `delegation/fangyan/bNN.md`，逐段判兩件事：

1. `domains`：這一段觸及哪些人生問題領域（下表 13 個 id，可以是空陣列）
2. `modes`：這一段用什麼方式說話（下表 8 個 id，可以是空陣列）

輸出寫成 `delegation/fangyan/out/bNN.json`，格式見文末。

## 這部書是什麼

《輶軒使者絕代語釋別國方言》，西漢揚雄撰、東晉郭璞注，記錄同一個意思在各地說成什麼詞。本庫落地 16 章：

| 章 | 內容 |
|---|---|
| 第 1 章 `刻方言序` | 宋人刻本序，談這部書的流傳、版本與校勘 |
| 第 2–14 章 `卷一`–`卷十三` | 正文。方言詞彙對照 |
| 第 15 章 `方言序` | 郭璞序，談這部書的來歷與他作注的用意 |
| 第 16 章 `跋李刻方言` | 後人跋，替訓詁之學辯護、批評當時學風 |

正文條目長這樣（`〈 〉` 裡是郭璞注音與注解）：

```
黨、曉、哲，知也。楚謂之黨，〈黨，朗也，解寤㒵。〉或曰曉，齊宋之間謂之哲。
台、胎、陶、鞠，養也。〈台猶頤也，音怡。〉晉衞燕魏曰台，陳楚韓鄭之間曰鞠……
```

**章名逐字照抄**（「卷一」不是「卷第一」，「刻方言序」不是「序」）。

## 唯一的通則性閘門

替換測試與敘事的刪除閘門在字書上都咬不到——字書不是要告訴讀者一件事，是要登錄一個詞。改問：

> **這一條除了「這個意思在哪裡說成哪個詞、那個詞怎麼念」之外，還說了關於人的什麼？**
>
> 沒有 → `[]`。
> 有 → 給領域。

「說了關於人的什麼」指人可以怎麼活、人有哪些惡、人與人之間如何。**不是**指這個詞的意思跟人有關。

## 硬撈風險（正文最容易錯的方向）

1. **被解釋的那個意思不是文本的內容。**「憮、㤿、憐、牟，愛也」是在說這四個字在各地都表示「愛」，不是在談愛。**要給 III，得是這一條真的在寫兩人之間的什麼。**同理「養也」不等於 IV、「知也／慧也」不等於 II、「好也」不等於 VII。**這一條吃掉正文絕大多數條目。**
2. **地域對照不是 V。**「楚謂之黨」「秦晉之間曰妍」「趙魏燕代之間曰姝」是語言地理，不是我群他群與偏見。要給 V，得是文本真的在講兩群人之間怎麼樣。
3. **郭璞注（`〈 〉` 內）多半是注音、異文、舉例、指出「亦四方通語」**，與內容無關。
4. **引書證是舉出處**：「《傳》曰」「《爾雅》云」是替詞義找旁證。
5. **地名注解不是內容**：「秦舊都，今扶風雍丘也」是地理考訂。

## 判空風險（序跋三章，反方向的風險在這裡）

**第 1、15、16 三章是散文，不適用條目的判法，要當論說文逐段認真讀。**它們談的是：這部書怎麼流傳與散佚、注書的人為什麼要做這件事、當時的學者怎麼看待訓詁之學。跋文明白批評「世之學者忽近而慕遠，捨實而徇名，高談性命，過自賢聖，視訓詁諸書往往束之高閣」——**那是在講治學者的毛病，該給就給。**

不要因為「這是一部字書」就整批機械填 `[]` 而不讀；也不要因為序跋在誇這部書就反射填領域。**逐段讀懂它在做什麼，然後照實記。**

## 13 個領域（`domains` 只能填這些 id）

| id | 名稱 | 涵蓋 |
|---|---|---|
| I | 存在與意義 | 人為何而活、意義從何而來、有無本末 |
| II | 自我與認同 | 我是誰、自我評價、身分、名與實 |
| III | 愛與親密 | 愛與性、被拒絕、承諾、信任與脆弱、溝通與被理解 |
| IV | 家庭與傳承 | 親子、宗族、繼承、教養、婚姻家內事 |
| V | 群體·社會·公義 | 孤獨與歸屬、友誼、我群他群與偏見、公義與權力、責任與領導 |
| VI | 情緒與內在生活 | 喜怒憂懼、內在經驗 |
| VII | 善惡·良心·品格 | 德性、良心、品格養成 |
| VIII | 工作·成就·召喚 | 勞動、職業、才能發揮、成就 |
| IX | 苦難·疾病·身體 | 痛苦、疾病、身體限制 |
| X | 無常·老·死·失去 | 死亡、衰老、失去 |
| XI | 自由·命運·改變 | 命定與自由、人能否改變 |
| XII | 信仰·神聖·超越 | 神聖、超越、信仰實踐 |
| XIII | 安頓·修復·平安 | 受苦之後如何自處、如何與處境相處 |

`Z-wisdom`、`X-modern`、`Y-nature` **不是領域**，絕不可出現在 `domains`。

## 8 個 discourse_mode（`modes` 只能填這些 id）

| id | 定義 | 判準 |
|---|---|---|
| `observation` | 陳述某物／某人實際如何 | 可被事實否證的描述句 |
| `proposition` | 主張某個因果或原理 | 有「A 故 B」的結構 |
| `prescription` | 規定應該如何 | 祈使或當為句 |
| `formalization` | 把規範化成可計算程序 | 有可執行的算法、方陣或制度表 |
| `narrative` | 用故事承載 | 有人物與情節 |
| `ritual` | 用儀節承載 | 規定動作、時序、器物 |
| `expression` | 第一人稱抒發而非第三人稱描述 | 說話者即當事人 |
| `worked_instance` | 以具體數字陳述一個問題實例及其答案 | 算書題例專用，**本書不會用到** |

要點：

- **正文條目一律 `observation`**，這是本書主導 mode
- **序跋裡作者自道（郭璞「余少玩《雅》訓，旁味《方言》，復為之解」）可給 `expression`**，因為說話者即當事人、沒有敘事框架
- 序跋裡追述這部書如何成書、如何散佚 → `narrative`；有「A 故 B」推理 → `proposition`
- **`modes` 不要疊到三個以上**，挑主導的一到兩個

## 硬規則

1. **`[]` 是合法答案**，`domains` 與 `modes` 都是。本書正文預期絕大多數段落 `domains` 為空，**那是正確結果不是失敗**。
2. **一段可多標領域，但不要濫用。預設一到兩個。**要標第三個，`reason` 裡必須寫得出「拿掉它這一段就少講了什麼」。
3. **不要更動 `chapter` 與 `para_index`**。章名逐字照抄；`para_index` 在每一章內從 1 重新編號，**回報時章名與 para_index 兩者都要給**。
4. **不要用你對揚雄、郭璞的既有知識去補文本沒說的東西。**
5. 原文有缺字、異體字、反切注音、`〈 〉` 夾注，那是來源格式，不影響判讀。

## 輸出格式

寫到 `delegation/fangyan/out/bNN.json`，UTF-8、LF、不要 BOM：

```json
{
  "batch": "b01.md",
  "rows": [
    {"chapter": "卷一", "para_index": 6, "domains": [], "modes": ["observation"],
     "reason": "登錄「愛也」在各地的說法與注音，是方言詞彙對照，沒說關於人的什麼"},
    {"chapter": "跋李刻方言", "para_index": 1, "domains": ["VIII"], "modes": ["proposition"],
     "reason": "批評當時學者捨實徇名、高談性命而輕視訓詁，講的是治學者怎麼走偏"}
  ]
}
```

**`rows` 必須涵蓋該批所有 (chapter, para_index)，一個都不能少、不能多。** 缺漏會整批退回。

`reason` 一句話即可，**判 `[]` 的段落也要寫 `reason`**，至少要指出它在做的是方言登錄、注音、書證，還是別的。

## 不要做的事

- 不要改 `translations/` 底下任何檔案
- 不要跑 git 指令（commit、reset、pull、checkout、stash 一律禁止）
- 不要改 `delegation/fangyan/` 的輸入 `.md` 與 `MANIFEST.json`
- 只寫 `delegation/fangyan/out/` 底下你這一批的那個 `.json`
