# 發包 spec：難經 段落級標註

## 你要做什麼

讀 `delegation/nanjing/bNN.md`，逐段判兩件事：

1. `domains`：這一段觸及哪些人生問題領域（下表 13 個 id，可以是空陣列）
2. `modes`：這一段用什麼方式說話（下表 8 個 id，可以是空陣列）

輸出寫成 `delegation/nanjing/out/bNN.json`，格式見文末。

## 這部書是什麼

《難經》託名秦越人（扁鵲），以八十一條問答解釋《內經》的疑難。全書體例**高度一致**：每一「難」先提一個問題（「十二經皆有動脈，獨取寸口，以決五藏六府死生吉凶之法，何謂也？」），接著以「然：」開頭作答。內容依序是脈學（1–22 難）、經絡（23–29 難）、藏象（30–47 難）、病證（48–61 難）、俞穴與針法（62–81 難）。

**這是一部純醫理問答書，沒有序、沒有作者自陳、沒有故事。**

## 唯一的通則性閘門

> **這一段除了「身體是怎麼運作的／這種病長什麼樣／該怎麼診治」之外，還說了關於人的什麼？**
>
> 沒有 → `[]`。
> 有 → 給領域。

「說了關於人的什麼」指的是：人怎麼對待自己的身體與性命、人在病與死面前是什麼處境、人與人之間如何。**不是**指這一段提到了病、死、身體部位或藏府。

## 本書的預設答案是 `[]`，但那不是配額

按上面的閘門讀，本書幾乎每一段都只在說身體怎麼運作與怎麼診治。**這很可能是本庫繼海島算經之後第二部 0／13 的書——那是有效結果，不是失敗。**

但**不要為了符合預設而整批判空**。判空的每一段都要在 `reason` 裡寫出它在做什麼（脈法、藏象、經絡、俞穴、針法、病證定義），寫不出來就表示沒讀。

## 最大的硬撈風險：**死、寿、魂、神、元氣這些字遍布全書**

- 「五至曰死，六至曰命絕」「沉細夜死，浮大晝死」→ 這是**脈象預後判語**，在說什麼脈對應什麼結局，不是在談死亡。`[]`
- 「名曰無魂，無魂者當死也，人雖能行，名曰行尸」→ 措辭鮮明，但它仍是一條脈診判語。`[]`
- 「脈有根本，人有元氣，故知不死」→ 以樹根譬喻說明尺脈的診斷意義。`[]`
- 「五藏有七神，各何所藏耶？」「藏者，人之神氣所舍藏也」→ 這是**藏象學說在定義藏府的功能**，`神`在這裡是生理術語，**不要因此給 XII**。`[]`
- 「損其肺者益其氣；損其心者，調其榮衛……此治損之法也」→ 治法條列。`[]`

**XII 要卡到最緊**：只有當文本真的在寫人與神聖的關係或信仰實踐時才給。醫理裡的「神」「魂」「魄」「精」是身體學說的詞彙。

## 真的命中要長什麼樣

若某一難離開了身體運作與診治，去講**人該怎麼活、醫者該怎麼做、人在病中的處境**，那才給領域。舉例（不保證書裡有，有才給）：

- 若有段落在說診病者應當如何盡責、不可草率 → VIII（職業）
- 若有段落在說病人自己該如何對待身體與生命 → IX 或 VII
- 若有段落在替這門學問的價值辯護 → 依內容判

**沒有就沒有。判 `[]` 不需要抱歉。**

## IX 這一格要特別想清楚

IX 是「苦難·疾病·身體」。這是一部醫書，直覺會想給。判準是同一道閘門：

- **身體作為知識與技術的對象**（經脈怎麼走、藏府藏什麼、什麼脈主什麼病）→ `[]`
- **身體作為人的處境**（有人在病裡、在身體的限制裡，而文本在寫那件事）→ IX

本書幾乎全屬前者。**不要為了讓 IX 有數字而硬撈。**

## `Z-wisdom` 陷阱

本書整部是「如何診、如何辨、如何刺」的技藝與體系，那屬 `Z-wisdom`（方法與體系），**`domains` 判空**。`Z-wisdom` 絕不可寫進 `domains`。

## 8 個 discourse_mode（`modes` 只能填這些 id）

| id | 定義 | 判準 |
|---|---|---|
| `observation` | 陳述某物／某人實際如何 | 可被事實否證的描述句 |
| `proposition` | 主張某個因果或原理 | 有「A 故 B」的結構 |
| `prescription` | 規定應該如何 | 祈使或當為句 |
| `formalization` | 把規範化成可計算程序 | 有可執行的算法、方陣或制度表 |
| `narrative` | 用故事承載 | 有人物與情節 |
| `ritual` | 用儀節承載 | 規定動作、時序、器物 |
| `expression` | 第一人稱抒發而非第三人稱描述 | 說話者即當事人 |
| `worked_instance` | 以具體數字陳述一個問題實例及其答案 | 算書題例專用，**本書不會用到** |

要點：

- **提問句（「……何謂也？」）本身給 `observation` 或 `proposition`，看它問的是什麼**；它不是 `expression`——提問者不是在抒發，是在設題
- 「然：」之後的推理若有「故 A 曰 B」的結構 → `proposition`，這是本書最常見的姿態
- **帶具體數字的推算**（「人一呼脈行三寸……一日一夜凡一萬三千五百息，脈行五十度」「陰得尺內一寸，陽得寸內九分」）→ 加 `formalization`。這是把身體寫成可計算的度量
- 治法條列（「損其肺者益其氣……」）→ `prescription`
- **`modes` 不要疊到三個以上**，挑主導的一到兩個

## 硬規則

1. **`[]` 是合法答案**，`domains` 與 `modes` 都是。負面結果本身是資料。
2. **一段可多標領域，但不要濫用。預設一到兩個。**
3. **不要更動 `chapter` 與 `para_index`**。章名是「第一難」到「第八十一難」，`para_index` 在每一難內從 1 重新編號，**回報時兩者都要給**。
4. **`Z-wisdom`、`X-modern`、`Y-nature` 不是領域**，絕不可出現在 `domains`。
5. **不要用你對中醫或《內經》的既有知識去補文本沒說的東西**，也不要判斷醫理對不對。
6. 原文標點使用半形 `?` `;` `:` 且有多餘空格，那是來源格式，不影響判讀。

## 輸出格式

寫到 `delegation/nanjing/out/bNN.json`，UTF-8、LF、不要 BOM：

```json
{
  "batch": "b01.md",
  "rows": [
    {"chapter": "第一難", "para_index": 3, "domains": [], "modes": ["proposition", "formalization"],
     "reason": "以一日一萬三千五百息推脈行五十度而復會寸口，是把脈行寫成可計算的度量以證獨取寸口之法，未觸及人的處境"},
    {"chapter": "第十四難", "para_index": 3, "domains": [], "modes": ["prescription"],
     "reason": "逐條列出五損各自的治法，是治療程序不是對人的看法"}
  ]
}
```

**`rows` 必須涵蓋該批所有 (chapter, para_index)，一個都不能少、不能多。** 缺漏會整批退回。

`reason` 一句話即可，但**判 `[]` 的段落也要寫 `reason`**——**本批幾乎全是判空，那些 reason 就是本批的全部價值**，至少要指出這一段在做的是脈法、經絡、藏象、病證還是針法。不要寫成「醫理」兩個字了事。

## 不要做的事

- 不要跑 git 指令（commit、reset、pull、checkout、stash 一律禁止）
- 不要改 `delegation/nanjing/` 的輸入 `.md` 與 `MANIFEST.json`
